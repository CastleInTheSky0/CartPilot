# CartPilot

AI 多平台抢购助手。

当前代码为既有的 Duo 网页助手版本；通用商品、多任务、Electron 和模型接入改造仍处于需求阶段。已确认的改造范围见 [Trellis PRD](.trellis/tasks/10-15-generic-purchase-desktop/prd.md)、[需求文档](docs/requirements.md)和[技术方案](docs/architecture.md)。以下使用说明对应当前代码。

## 当前版本：Duo 首发助手

Windows 本地购买助手，支持 Apple 中国官网、淘宝、天猫、京东和抖音商城的独立配置。React + TypeScript + Vite 界面，Node.js + Express 服务，默认通过官方 Playwright Extension 接入日常使用的 Google Chrome，沿用该 Chrome 资料的登录会话。也可切换到各平台独立资料的助手窗口。

可以选择一个平台执行，也可以同时监控多个平台。**首个出现可识别购买入口的渠道取得唯一购买资格，其他渠道停止；所有渠道共用一份订单提交锁。** 这不是库存或购买成功的保证。某渠道进入结账后遇到验证、缺货或结果不明，会等待人工处理，不会擅自换渠道再次下单。

## 使用

1. 安装 Node.js 22.12 或更高版本及 Google Chrome。首次双击 `安装依赖.cmd` 安装依赖、测试用 Chromium 并构建界面。
2. 双击 `启动助手.cmd`，打开 [本机应用](http://127.0.0.1:4317)。保持服务窗口开启。
3. 在“浏览器接入”点击“安装官方扩展”，将 [Playwright Extension](https://chromewebstore.google.com/detail/playwright-extension/mmlmfjhmonkocbjadbfplnigmagldckm) 安装到你已登录商城的 Chrome 用户中。点击“连接普通 Chrome”，在扩展打开的授权页面允许本次连接。然后切换各渠道，刷新标签列表并“接入所选标签页”。先在普通 Chrome 打开所需商城页面；不同渠道分别选择标签页。Chrome 有多个用户时，可展开资料目录设置，填 `Default` 或 `Profile 1` 等目录名。核对收货地址、付款准备和预约资格。
4. 填写完整商品详情链接。也可点击“查找商品”，打开目标详情页后点“读取当前商品”。搜索页、短链接、活动页不能直接作为购买链接。淘宝渠道也接受天猫商品链接，两处配置与会话分别保留。京东不同规格可能对应不同商品编号，请使用目标规格的链接。
5. 逐个平台设置颜色、容量、预算与北京时间的开售时间。备用链接沿用该渠道的规格、预算、计划和自动提交设置，只有到整页刷新时间才切换主备商品。各店铺开售时间可能不同。
6. 选择“多平台同时监控”，勾选参与的渠道。未配置商品的渠道会明确显示待配置，勾选后需补齐链接才能启动。
7. 自动提交按渠道单独开启；默认人工确认。启动前的窗口列出全部参与渠道及各自预算与执行方式。“立即执行”会跳过倒计时并进入真实购买流程。
8. 需要接手时，在对应渠道的浏览器处理，然后点该行“已操作，继续”。若正在冷却，需要先等待倒计时结束。监控期间某个渠道等待验证，不会阻塞其他渠道。取得购买资格后，其余渠道保持停止。

任务依赖本机时间，请提前同步 Windows 时间，并保持电脑唤醒、网络、服务和浏览器开启。关机、休眠、关闭服务期间不会运行，重启后不会自行恢复任务。每个平台的最长运行时间从自己的计划开始计时，包含人工等待。

“扩展已连接”与商城“已登录”是两种独立状态。渠道选项、渠道下方的登录状态栏和左侧浏览器入口均显示各平台的登录状态。接入后每 10 秒读取所选页面，也可点击“重新检测”，不会刷新商城或请求登录接口。“已登录”表示检测到可见的账户昵称或退出登录控件；登录表单、未登录提示或会话失效显示“需要登录”；验证、访问限制、无法识别、检测过期或断开服务时显示“暂无法确认”。未接入标签页时显示“未检测”。页面未暴露账户信息时，可手动展开账户菜单后再检测；未接入的其他窗口不作为登录证据。

扩展模式不会复制 Cookie 或 Chrome 资料，直接接入普通 Chrome，无需使用远程调试参数重启 Chrome。助手只操作明确接入的标签页及其弹窗，不接管无关新标签页。断开扩展会停止购买任务、释放连接，保留普通 Chrome 及其网页。重启服务后需要重新连接与选择标签页。扩展未安装、连接断开或未选标签页时会提示处理，不会自动切换执行方式。

需要继续使用旧方式时，选择“助手独立窗口”，在助手打开的窗口登录。该模式沿用 `.data/chrome-profiles/` 下的平台资料，普通 Chrome 的会话不会自动复制；已有 Chrome 和升级前 Chromium 资料继续保留。

## 页面读取、刷新与冷却

- 页面读取默认每 10 秒执行，只检查当前 DOM、规格和购买入口。页面自身的脚本仍可能联网。已选中的规格保持不动，当前商品页可复用时不会重新导航。
- 整页刷新独立计时：默认平时 120 秒一次，开售前后各 2 分钟内 30 秒一次。界面可调整日常刷新（60–600 秒）、开售刷新（15–120 秒）及本地读取间隔（3–60 秒）。等待期间预加载页面、选好规格，达到开售时间才允许进入购买。
- 多平台自动整页导航启动至少间隔 1.5 秒，同一平台至少间隔 5 秒且串行执行。淘宝与天猫共享同一访问组。此限制管理助手主动发起的页面导航，不替代网站自身的网络请求。
- 网络读取连续失败时等待 30、60 秒后重试；达到 3 次后要求人工检查。退避策略上限为 5 分钟。
- `429` 按 `Retry-After` 等待，支持秒数、HTTP 日期和服务器时钟偏差；没有有效等待提示时默认冷却 5 分钟。`403／541` 至少冷却 10 分钟，网站要求更久时取更长时间。
- 冷却期间停止自动访问，倒计时结束后仍等待人工检查。运行中使用“已操作，继续”；停止状态下使用“已验证，解除暂停”。恢复后优先读取保留的当前页面，再按刷新计划执行。
- 访问限制保存到 `.data/access-state.json`，停止、重新启动任务、只读检查和重启服务均不会自动清除。淘宝与天猫共享限制。访问限制记录损坏或无法保存时停止自动导航，需先修复本机存储。

这些措施用于减少重复访问，仍可能遇到平台验证；真实平台的限制以其提示为准。

Apple 页面颜色为星光白色、夜空色；参考价：256GB ¥15,999，512GB ¥17,999，1TB ¥21,499，2TB ¥26,499。商城售价、预算和开售时间独立配置。产品图来自 Apple 购买页，应用不隶属于任何商城。

## 自动化范围

- Apple：识别规格，跳过折抵换购及 AppleCare+，确认购物袋为空后加购，核对订单并推进已识别结账步骤。
- 淘宝／天猫／京东：识别网页规格和“立即购买／立即抢购”入口，进入订单页后核对商品编号、配置、数量和总价。商城已有购物车不参与直接购买流程。
- 抖音：处理可在网页完成的购买入口。需要扫码、打开 App、移动端流程或第三方支付时交给人工；未验证实际商品网页。
- 各平台按钮或页面结构无法识别时会暂停。“高级适配”按渠道保存 CSS 选择器，可补充标题、规格、购买、商品条目、数量、店铺、总价和提交控件。自定义选择器不能跳过结账域名、商品编号、配置与预算核对。

所有渠道只购买 1 台。最终核对必须满足：已识别的结账页面、唯一商品、目标商品编号（商城）、完整的型号／颜色／容量、明确数量 1、唯一人民币总价且不超过预算。可选店铺名称要求完整匹配。分期、定金、尾款、额外商品和信息不明确时会暂停。

登录、验证码、访问限制（403／429／541）、收货必填信息、条款和支付验证需要用户完成。不会绕过平台验证。扩展接入沿用普通 Chrome 会话，但网站仍可能要求验证；现有冷却与人工复核要求跨连接方式保留。

自动提交前先持久化记录，再重新核对页面，最多点击一次。人工确认订单前也会保留交接记录。记录锁住全部渠道，程序崩溃或重启后仍生效；结果不明不会重复提交。重新执行需先核对平台订单，再复核提交记录。该保护不能阻止用户在浏览器中自行重复购买。

订单确认页与订单号被识别后才显示完成，**不代表已付款或已发货**。真实首发下单、付款和订单完成流程尚未实测。测试中的成功只代表隔离页面通过流程检查。

## 本地数据

- `.data/workspace.json`：各平台独立配置、参与渠道与执行方式。首次启动会读取旧的 `.data/settings.json`，补齐默认字段，保留旧配置文件和 Apple 登录资料。
- `.data/browser-connection.json`：浏览器连接方式与可选 Chrome 资料目录名。缺失时默认扩展接入，不保存扩展令牌、标签页 ID 或商城会话。
- `.data/chrome-profiles/apple/`、`taobao/`、`tmall/`、`jd/`、`douyin/`：助手独立窗口模式的各平台专用登录资料。登录与执行使用相同目录，不复制日常 Chrome 的默认用户资料。
- `.data/browser-profile/` 及 `.data/browser-profile-{平台}/`：升级前的 Chromium 资料，继续保留。显式设置 `DUO_BROWSER_CHANNEL=chromium` 后可使用这些旧资料及已安装的 Chromium，界面会显示实际浏览器类型。
- `.data/access-state.json`：需要人工复核的访问限制及冷却结束时间。
- `.data/events.ndjson`：运行日志，界面及导出显示最近 150 条。
- `.data/submission.json`：最近一次提交或人工确认交接记录，包含平台及实际商品链接。

本地资料含登录会话，请勿上传或分享。应用不接收账号密码；在商城网页输入的资料由商城和 Chrome 处理。扩展模式直接使用已连接 Chrome 的会话，不导入或导出会话文件。

服务仅绑定 `127.0.0.1`，检查 Host、Origin 和写操作客户端标记，无云端服务或遥测。访问商城时会正常联网。系统通知需要通过右上角铃铛授予权限。

## 开发与验证

工程规则见 [工程与代码规范](docs/engineering-standards.md)，包含 Electron 目录分层、TypeScript、命名和格式约定。`npm run check:lines` 检查 400 行约束及旧文件禁止增长的基线，构建前自动运行；`npm run check:lines:strict` 用于检查全部文件是否完成拆分。

```powershell
npm ci
npx playwright install chromium --no-shell
npm run dev
# 前端 127.0.0.1:5173，后端 127.0.0.1:4317

npm run build
npm test
npm start
```

`npm test` 串行运行，避免同时启动多个测试浏览器。浏览器测试拦截全部商品网络请求并使用本地页面响应，不访问真实商城、不加购、不下单。覆盖 Apple 回归、四个平台直接购买流程、唯一购买与提交锁、预算与商品核对、定时取消、DOM 更新无需刷新、开售前预选规格、主备链接按刷新切换、重复任务合并、Retry-After 与冷却持久化、重启和只读检查不能清除限制。扩展测试通过真实 `Browser.bind → chromium.connect` 本机连接验证标签页筛选、显式接入、登录检测、弹窗归属、取消与断开保留网页，以及离线订单只提交一次。安装了 Chrome 的 Windows 主机还会使用临时测试资料验证真实 Chrome 重启后保存会话，其他环境跳过这一项。

扩展适配器调用已导出的内部 `playwright-core/lib/coreBundle` 接口，因此将 Playwright 固定为 **1.64.1**。官方中继在独立子进程运行，取消授权等待时只结束中继；连接普通 Chrome 时使用 `noDefaults`，不改写用户浏览器默认配置。升级 Playwright 时需同步核对中继接口、本机命名管道及断开语义，再运行完整回归。真实 Chrome 的扩展安装与授权仍需在该 Chrome 中完成；离线测试不代表真实商城已接入或真实首发下单成功。

可通过 `DUO_PORT` 指定端口（开发代理默认仍为 4317），通过 `DUO_DATA_DIR` 指定独立数据目录。不要并行启动两个指向相同资料目录的实例。内存较紧张时，先关闭多余浏览器页面再构建；PowerShell 可在构建前设置 `$env:GOMAXPROCS='2'` 限制编译器并行度。
