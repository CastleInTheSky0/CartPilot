## M1：桌面技术验证

- 已接入 Electron 44.7.2、electron-vite 6.0.0、electron-builder 26.15.3 和 Zod 4.6.7，锁定具体版本。

- Renderer 使用受限 preload；主进程校验 IPC 来源、主 frame 和输入，启用 sandbox、contextIsolation，限制导航、新窗口和权限。
- 单实例按用户数据目录管理；桌面数据默认在 Electron userData，测试用 `CARTPILOT_DATA_DIR` 指定独立绝对路径。
- 命令：`npm run desktop:dev`、`npm run desktop:build`、`npm run desktop:start`、`npm run desktop:test`。

### 扩展桥与连接验证

- 提取现有连接、端点校验和官方中继模块，旧服务使用兼容入口，保留固定 Playwright 1.64.1 与 `noDefaults` 语义。

### 扩展中继 WebSocket 连接修复

- 用户在桌面开发版点击扩展授权后，遇到 `Failed to connect to MCP relay: WebSocket error`。在临时 Chromium 资料中加载已安装的官方扩展 0.4.0 复现：官方中继仍在监听，但 `localhost` 默认解析出的 IPv6 回环 `::1` 在本机访问时返回 `EACCES`。
- 官方中继进程启动时使用 Node 的 DNS API 优先 IPv4，使官方服务监听 `127.0.0.1`。设置仅在独立中继进程生效，保留官方协议、授权及回环地址限制。
- 新增打包回归：以 Electron 的 Node 模式加载实际构建的中继，在 IPv6 优先环境截获浏览器启动地址并进行真实 WebSocket 握手；不启动用户 Chrome，也不模拟浏览器协议。已确认修改前失败、修改后通过；该测试同样覆盖实际安装目录中的中继。
- 开发构建的完整 Electron → utilityProcess → Node 中继 → 官方扩展链路，在临时 Chromium 资料和离线京东页面中通过两轮授权、列表、接入、登录读取、断开与重连。旧标签标识被拒绝，商品页仅请求一次，断开及退出应用后页面均保留。测试仅通过启动包装器指定隔离浏览器，不复制用户登录资料。
- `npm run desktop:build`、`npm run desktop:test`（16 项）、旧版扩展回归（10 项）、严格类型及行数检查通过。隔离完整链路报告为 `output/playwright/extension-desktop-verification.json`，截图为 `extension-desktop-round-*.png`。

### 数量、预算与多笔订单事务

- 增加任务、运行、购买意图、单次提交记录、订单、结账资源锁与审计事件的 Drizzle 迁移。SQLite 使用立即写事务，原子核对配额、所有平台共享预算、标签页和账户资源；淘宝／天猫共享账户结账资源。
- 提交前持久化唯一提交标识及未知结果，自动提交与人工确认沿用任务设置。同一意图不能重复取得提交授权；订单证据必须关联本次提交，平台与订单号跨任务去重。
- 提交前重新核对商品身份、SKU、通用规格、数量、店铺、购买方式、优惠后单价及含运费总额。证据过期、复杂订单、金额不明确或预算不足均不授权。
- 停止和崩溃恢复只释放尚未进入提交阶段的预留；未知提交保留数量、预算与资源占用。新运行继承累计进度；待支付订单计入件数，取消、关闭或支付超时保留原进度及审计，不能自动补买。
- 新增 `npm run desktop:test:storage`，使用 Electron 自带 Node 与实际原生 SQLite 执行隔离集成测试，避免 Node／Electron ABI 混用。12 项通过，包括两个独立进程同时争用最后一件及剩余预算；`npm run desktop:build`、13 项桌面测试和行数检查通过。
- 当前尚未把订单授权接口暴露给 renderer 或真实商城执行器，页面适配与任务工作台仍按后续阶段实施。状态机与旧数据迁移继续开发，PRD 整体验收项保持未勾选。

### 任务状态与取消

- 固定 XState 稳定版 5.33.2，通过准备与执行端口管理待复核、准备、就绪、等待开售、执行、人工接手、冷却、停止、目标完成和错误状态，不恢复应用重启前的执行授权。
- 准备结果校验任务与候选身份和有效期；计划过期或页面变化要求重新准备。等待开售、最长运行时限及取消由 XState actors 管理，取消信号传递到准备／执行端口，离开执行状态立即停止持久化运行。
- 停止后的执行器不能继续预留或取得提交授权；已经进入提交阶段的记录与占用继续保留。完成状态由数据库中的已确认件数决定，执行器返回结束或一笔订单成功均不能代替任务目标完成。
- 新增 7 项真实 SQLite 状态机测试，覆盖定时取消、异步结果失效、计划过期、未决提交停止、多笔完成及错误任务身份；集成测试共 19 项通过。严格类型和行数检查通过；此前启动的旧版 72 项完整回归也已通过。
